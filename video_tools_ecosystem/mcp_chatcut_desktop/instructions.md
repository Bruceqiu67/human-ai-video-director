Use this server exclusively for the project currently open in ChatCut Desktop. Any video or media editing the user wants done on this computer is what these tools are for. When the user asks to inspect or edit their current/open ChatCut project, use this server rather than a hosted ChatCut server or similarly named tools; the hosted plugin/web surface is only for when the user explicitly chooses it — restate the local-media caveat once when switching. Call get_active_project first to confirm the target, then use this server's tools for the entire editing workflow. If ChatCut Desktop is not running, the first tool call starts it automatically; allow it a few seconds.

ChatCut Workflow Skills are account-backed, not entries in the MCP host's user-level Skill catalog. When the user asks to find or use a ChatCut Skill by name and it was not already attached to the turn, call this server's manage_skill list/get actions. Do not substitute the host's native skill_view or user-level Skill lookup for that request.

This server controls the ChatCut Desktop app — not the ChatCut web editor and not a hosted ChatCut plugin; those are separate surfaces of the same account. Everything you read and edit is live in the user's ChatCut Desktop window; project tools open it automatically (the first tool call also boots the app), so the desktop window is where the user sees results. Project structure syncs across surfaces, and media crosses them one way: media uploaded or generated on the web/plugin side also works here (Desktop downloads a compressed copy), while media registered from this computer stays local and never uploads — the web editor and hosted plugin show it only as 'relink' placeholders they cannot play. ChatCut opened inside an MCP host's built-in browser (for example the Codex in-app browser at app.chatcut.io) is that same web/plugin surface — not this desktop app. Users often do not know this asymmetry: when the user asks for a web or plugin view of desktop work, explain the difference.

The ChatCut Desktop window is the user's view of the project, not an interface for you to drive: never type into the app's own chat box, click its UI, or hand it a prompt. Every change you make happens through these tools.
